# Потоки данных CENTRAL и STORE

| Поле | Значение |
| --- | --- |
| Идентификатор / версия | WH-DF-001 / 1.3 |
| Дата | 12.11.2026 |
| Ответственная группа | Команда 3 — Warehouse |
| Статус | Проект для согласования |
| Источники | [DOC-05](../../../00_Documentation/DOC-05.md), [DOC-06](../../../00_Documentation/DOC-06.md), [DOC-08](../../../00_Documentation/DOC-08.md); [INT-001/1.3](../../../06_integration_architecture/INT-001-target-model.md) |
| Связанные требования | WH-R-01/02/09/15/21/22/23 — [каталог](../../01_Business_Architecture/Requirements/WH-REQ-001-requirements.md) |

Все перечисленные межсистемные обмены проходят IS-07. Источник бизнес-факта, транспортный ACK и применение факта потребителем имеют разные подтверждения.

| Поток | Источник → потребитель | Объект и контроль |
|---|---|---|
| F1 | ERP → WMS | Product/sourceVersion и ожидаемая поставка; неизвестная единица отклоняется |
| F2 | Онлайн/ERP ↔ WMS | Reserve, confirm-paid, статус/отмена; прежние ключи и expectedVersion |
| F3 | ERP → WMS | Одно задание по erpOrderId/orderId/version и прежнему reservationId |
| F4 | WMS → онлайн/BI; ERP ↔ WMS | Онлайн/BI получают Stock CENTRAL; ERP — факты исполнения и ответ INT API-04 без постоянной копии остатков |
| F5 | Inventory магазина → WMS | STORE movements, журнал с непрерывной границей; факт не теряется при неизвестном ответе |
| F6 | Inventory ↔ WMS | Heartbeat, missingRanges и контрольный снимок; не переписывать WMS произвольной локальной копией |
| F7 | Закупки ↔ WMS; WMS → Inventory/BI | Закупки читают STORE Stock и StoreSync по INT API-04 без копии; магазин/BI получают свои проекции |
| F8 | ERP → WMS → магазин | План/передача/частичная приёмка transferId; движение пути и двух площадок раздельно |
| F9 | WMS → аналитика | История и snapshot boundary/watermark, без запуска реальных операций при загрузке истории |

Поступление: план ERP → физическая приёмка → движение WMS → Stock → учёт ERP. Исполнение: один резерв → оплаченный hold → учётный заказ ERP → задание WMS → подбор → передача. Магазин: чек/операция → локальный журнал → применение WMS → STORE Stock → запрос закупок к WMS. Пополнение: план → CENTRAL-отгрузка/путь → уникальные магазинные приёмки → STORE.

ERP при недоступности WMS приостанавливает автоматическое пополнение: сохранённый план не заменяет текущий остаток. После EVT-04/25 закупки запрашивают WMS повторно (INT T-41).

Источник хранит sourceVersion и eventId; получатель — inbox и последнюю применённую версию агрегата. Полный снимок может перескочить версию Stock, если так определён контракт; для последовательного STORE-журнала пропуск sourceSequence требует догрузки. Время часов само по себе не определяет порядок.

В исходниках нет утверждённых TTL, freshness и пиков. Пилотные предложения общего пакета (Stock p95 ≤60 с, сигнал asOf >120 с) не заменяют согласование STORE heartbeat, дедлайнов и полного профиля нагрузки. Аналитические потребители изолируются от критичного reserve.
