## Модель доступа To-Be

| Роль | Разрешено | Ограничение |
| --- | --- | --- |
| Кладовщик / комплектовщик | Видеть своё задание, подтверждать физические шаги, фиксировать расхождение | Не менять мастер-товар, не утверждать собственную инвентаризационную корректировку |
| Начальник склада | Распределять задания, разбирать исключения, утверждать корректировки в пределах полномочий | Не управлять финансовыми проводками/ценами |
| Директор по логистике | Утверждать правила и пороги эскалации, видеть показатели | Не подменяет ежедневный факт операции без аудита |
| Оператор заказа | Смотреть остаток/статус, резервировать и запросить отмену | Не подтверждает приёмку/передачу от имени склада |
| Финансовый специалист | Проверять учётные документы и сверку | Физический остаток исправляется через согласованный складской процесс |
| Администратор | Настройка и восстановление | Технический доступ отделён от права одобрять складское движение |
| Интеграционный клиент | Только конкретный API/тип события | Разные учётные записи, scope и журнал для каждой системы |
| Аналитик | Читать согласованные проекции | Не изменять оперативные данные WMS |

Разделение подготовки и утверждения корректировки — предложенный контроль, который уточняется по численности смен. Централизованная идентификация/SSO, MFA для согласованного набора критичных операций, роли и минимальные привилегии следуют DOC-17. Удобство и техническая поддержка терминалов проверяются на пилоте.

## Данные и журналирование

Межсистемные соединения защищены; сервисные полномочия ограничены. В складском задании хранятся только данные, необходимые для исполнения и передачи: идентификатор заказа, строки, способ/точка передачи и при необходимости разрешённые реквизиты получателя. Полная карточка CRM, бонусный счёт и платёжные реквизиты не копируются в WMS.

Аудит включает actorId/clientId, operationId, объект, действие, время, основание, значения до/после и результат. Пароли, токены и лишние персональные данные в журналы не попадают. Право очистки журналов отделено от бизнес-пользователей; срок хранения и доступ утверждаются владельцами, произвольный срок здесь не назначается.

## Проверка угроз и контролей

| Сценарий | Контроль | Проверка |
| --- | --- | --- |
| Онлайн-клиент вызывает confirm-handover | Авторизация по операции и роли | `403`, остаток не меняется |
| Повтор перехваченной команды | Защищённый канал, идентификация клиента и идемпотентность | Нет второго движения |
| Изменение количества после согласования | Версия объекта и аудит | Конфликт `409`, требуется повторное согласование |
| Доступ к чужому складу/заказу | Ограничение области данных роли | Запрос не раскрывает запрещённые строки |
| Удаление следа корректировки | Защищённый аудит и ограничение прав | Изменение отражается в независимом контроле |
| Секрет в конфигурации Git | Отдельное хранение и проверка перед публикацией | В артефактах только названия параметров, без значений секретов |
