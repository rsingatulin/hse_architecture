## Доменная декомпозиция

В масштабе RetailMax логистика — Supporting Domain. Внутри него запас и исполнение — ключевые возможности домена; слово Core здесь относится к Warehouse, а не объявляет склад главным конкурентным преимуществом всей компании.

| Субдомен | Тип | Обоснование |
|---|---|---|
| Запас и резерв | Core внутри Warehouse | Решение о доступности и единственный подтверждённый запас CENTRAL/STORE |
| Исполнение и перемещение | Core внутри Warehouse | Проверяемая передача и отсутствие двойного физического исполнения |
| Приёмка и размещение | Supporting | Перевод поставки в фактическое хранение |
| Инвентаризация и качество | Supporting | Обоснованные корректировки, сверка и аудит |
| Синхронизация магазина | Supporting | Устойчивая доставка первичных фактов STORE к владельцу запаса |
| Идентификация, транспорт, наблюдаемость | Generic | Используются общие возможности предприятия |
| Прогноз нагрузки | Supporting, опционально | Помощь планированию смен; не владелец остатка |

## Bounded Context и единый язык

| Контекст | Термины и данные | Граница / владелец |
|---|---|---|
| Управление запасом (Inventory Authority) | StorageSite, Stock, Reservation; «подтверждённый запас», «резерв», «заблокировано» | Логистика/WMS; атомарные инварианты CENTRAL и STORE; STORE-резерв не вводится автоматически |
| Исполнение склада (Warehouse Execution) | Receipt, FulfillmentTask, Shipment, Transfer; «принято», «подобрано», «передано», «в пути» | Склад/WMS; не создаёт заказ канала и финансовую продажу |
| Операции магазина (Store Operations) | StoreJournal, StoreMovement, SyncState; «локальный факт», «ожидает», «применено» | Логистика; POS даёт факт продажи. Локальная копия не становится вторым мастером |
| Контроль запасов (Inventory Control) | InventoryCount, Adjustment, ReconciliationCase | Начальник склада/ответственный магазина; согласует корректировку, не стирает историю |
| Аналитика склада (Warehouse Analytics) | Версионированные факты и показатели этапов | Логистика определяет смысл; аналитика строит проекции, не пишет Stock |

Контексты — границы модели и языка, не обязательные сетевые микросервисы. Управление запасом (Inventory Authority) и Исполнение склада (Warehouse Execution) первоначально реализуются модулями одной WMS и одной поддерживаемой транзакционной границей. Это позволяет атомарно согласовывать запас, резерв, задание и журнал фактов. Их разделение по БД потребовало бы нового ADR.

## Сервисы и зависимости

| ID / сервис | Ответственность и данные | Размещение / API | Потребители |
|---|---|---|---|
| WH-SVC-01 Запасы и резерв | Stock CENTRAL/STORE; reserve/confirm-paid/release; версии | C2 WMS; WH API-01/02/03/13/14 | Онлайн, ERP через IS-07 |
| WH-SVC-02 Приёмка и размещение | План/факт приёмки, допустимое размещение | C2; WH API-04/05/12 | Склад, ERP/закупки |
| WH-SVC-03 Исполнение и перемещение | Задание, отмена, передача, товар в пути | C2; WH API-06–09/15/18 | ERP, склад, магазин |
| WH-SVC-04 Инвентаризация | Пересчёт, утверждение и сверка | C2; WH API-10/11 | Уполномоченный руководитель, ERP |
| WH-SVC-05 Складской адаптер | Преобразование, техническая доставка и диагностика | Адаптер Warehouse в общем IS-07; нет собственного бизнес-запаса | Все разрешённые внешние клиенты |
| WH-SVC-06 Поставка аналитических данных | Факты и контрольные снимки одной границы | Publisher/адаптер; события и WH API-11 | BI; закупки используют запрос INT API-04 |
| WH-SVC-07 Локальный учёт магазина | Локальная запись движения, pending и обратное подтверждение | C6 магазина; WH API-16/17 через IS-07 | POS и сотрудник магазина |

Владелец семантики сервисов — логистика, техническое сопровождение — ИТ. SSO, Gateway и брокер используются корпоративные. Для критичных API применяется ограничение ≤500 мс по DOC-17; для длительной команды 202 означает только устойчивое принятие, результат читается отдельно. Конкретный стек WMS и поддержка расширений ещё не подтверждены.

## Карта взаимодействия контекстов

ERP поставляет справочник Product, ожидаемую поставку и единственное задание. Контекст «Операции магазина» передаёт первичный факт через адаптер (Anticorruption Layer) в контекст «Управление запасом». WMS передаёт факты Transfer для учёта ERP. Закупки читают Stock и свежесть по INT API-04 без постоянной копии; EVT-04/25 инициируют повторное чтение. BI получает разрешённую аналитическую проекцию. Канал оформления использует единый reserve и прежний reservationId. Общая платформа выполняет техническую координацию по бизнес-правилам владельцев.
