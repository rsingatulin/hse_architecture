# Документ 9. Устав проекта цифровой трансформации (Project Charter)

## 1. Общие сведения

**Проект:** Разработка целевой архитектуры корпоративной информационной системы RetailMax

**Заказчик проекта:** Генеральный директор RetailMax

**Куратор проекта:** ИТ-директор

**Дата начала проекта:** 1 сентября 20XX года

**Планируемая продолжительность:** 12 месяцев

---

# 2. Основание для запуска проекта

В результате анализа деятельности компании было установлено, что существующая корпоративная информационная система перестала обеспечивать необходимый уровень поддержки бизнес-процессов.

Основными причинами запуска проекта являются:

- рост объема онлайн-продаж;
- увеличение количества интеграций между информационными системами;
- необходимость сокращения сроков вывода новых цифровых сервисов;
- увеличение стоимости сопровождения существующей архитектуры;
- необходимость использования современных технологий контейнеризации, облачных решений и искусственного интеллекта.

Совет директоров принял решение о разработке новой корпоративной архитектуры.

---

# 3. Цель проекта

Разработать целевую архитектуру корпоративной информационной системы, обеспечивающую поддержку стратегии развития компании на ближайшие 3–5 лет.

---

# 4. Задачи проекта

В рамках проекта необходимо:

- проанализировать существующую архитектуру предприятия;
- определить архитектурные проблемы;
- разработать целевую архитектуру;
- предложить модернизацию информационных систем;
- определить подходы к интеграции приложений;
- разработать технологическую архитектуру;
- подготовить технико-экономическое обоснование;
- оценить риски реализации проекта;
- разработать дорожную карту внедрения.

---

# 5. Границы проекта

## В проект входят

- пять ключевых бизнес-процессов предприятия;
- семь корпоративных информационных систем;
- архитектура приложений;
- архитектура данных;
- технологическая архитектура;
- интеграционная архитектура;
- предложения по использованию технологий искусственного интеллекта.

## В проект не входят

- разработка программного обеспечения;
- внедрение информационных систем;
- закупка оборудования;
- миграция данных;
- изменение организационной структуры предприятия.

---

# 6. Основные заинтересованные стороны

| Роль | Ответственность |
|------|-----------------|
| Генеральный директор | Заказчик проекта |
| ИТ-директор | Куратор проекта |
| Коммерческий директор | Представитель бизнеса |
| Директор по логистике | Представитель бизнес-процессов склада |
| Директор по маркетингу | Представитель процессов CRM и аналитики |

---

# 7. Организация проектной команды

Архитектурная команда разделена на пять рабочих групп.

| Группа | Бизнес-процесс |
|---------|----------------|
| Группа 1 | Продажи |
| Группа 2 | Закупки |
| Группа 3 | Управление складом |
| Группа 4 | Интернет-продажи |
| Группа 5 | Программа лояльности и аналитика |

Каждая группа отвечает за полный цикл архитектурного проектирования своего бизнес-процесса.

---

# 8. Основные результаты проекта

По итогам выполнения проекта должны быть подготовлены следующие материалы.

## Архитектурные документы

- описание архитектуры предприятия;
- архитектурные требования;
- каталог сервисов;
- архитектурные решения (ADR).

## Архитектурные модели

- BPMN;
- ArchiMate;
- C4 Model;
- UML Component Diagram.

## Документы по технологической архитектуре

- схема развертывания;
- описание контейнерной архитектуры;
- концепция Kubernetes-кластера;
- предложения по использованию Cloud Native.

## Документы по управлению проектом

- технико-экономическое обоснование;
- реестр рисков;
- дорожная карта внедрения.

---

# 9. Основные ограничения

При выполнении проекта необходимо учитывать следующие ограничения.

- Замена ERP-системы не допускается.
- Компания должна продолжать работу во время реализации проекта.
- Все решения должны быть совместимы с существующими данными.
- Архитектура должна предусматривать возможность дальнейшего масштабирования.
- Используемые решения должны основываться на открытых стандартах.

---

# 10. Основные допущения

При выполнении проекта принимаются следующие допущения.

- Все необходимые специалисты предприятия доступны для проведения интервью.
- Информация, содержащаяся в документах проекта, является актуальной.
- Руководство предприятия готово рассматривать предложения по модернизации архитектуры.
- Возможно постепенное внедрение архитектурных изменений.

---

# 11. Критерии успешного завершения проекта

Проект считается успешно завершенным, если:

- разработана целевая архитектура предприятия;
- подготовлены все предусмотренные архитектурные модели;
- архитектурные решения соответствуют стратегии цифровой трансформации;
- выполнено технико-экономическое обоснование;
- разработаны план внедрения и дорожная карта;
- результаты проекта успешно представлены архитектурному комитету.

---

# 12. Порядок выполнения проекта

Проект выполняется поэтапно.

1. Анализ текущего состояния.
2. Анализ бизнес-процессов.
3. Разработка архитектурных моделей.
4. Проектирование архитектуры приложений.
5. Проектирование технологической архитектуры.
6. Проектирование использования технологий искусственного интеллекта.
7. Экономическая оценка проекта.
8. Анализ рисков.
9. Подготовка плана внедрения.
10. Защита архитектурного проекта.

---

# 13. Задание проектным группам

Каждая группа должна выполнить полный цикл архитектурного проектирования для закрепленного бизнес-процесса.

По завершении работы необходимо представить:

- описание текущего состояния (As-Is);
- описание целевого состояния (To-Be);
- архитектурные модели;
- перечень архитектурных решений;
- технико-экономическое обоснование;
- анализ рисков;
- план внедрения.

Итоговые материалы всех пяти групп должны быть объединены в единую корпоративную архитектуру предприятия.

---

# 14. Задания студентам

На основании настоящего документа необходимо:

1. Определить область ответственности своей проектной группы.
2. Подготовить план выполнения архитектурного проекта.
3. Определить состав создаваемых архитектурных артефактов.
4. Организовать совместную работу в архитектурном репозитории.
5. Обеспечить согласованность разрабатываемых решений с результатами других групп.
