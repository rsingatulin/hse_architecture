# Документ 4. Каталог информационных систем предприятия

## 1. Общая информация

В компании RetailMax используются семь основных информационных систем, обеспечивающих выполнение ключевых бизнес-процессов предприятия.

Информационные системы внедрялись в разное время различными поставщиками. Между системами существует несколько интеграций, однако отсутствует единая архитектура приложений.

В рамках проекта цифровой трансформации предполагается разработать целевую архитектуру приложений предприятия.

# 3. Описание информационных систем

## IS-01. ERP

### Назначение

ERP является основной корпоративной системой учета.

### Основные функции

- управление закупками;
- учет товаров;
- управление поставщиками;
- финансовый учет;
- учет продаж;
- учет остатков;
- формирование первичных документов.

### Основные пользователи

- отдел закупок;
- финансовый отдел;
- руководство;
- сотрудники склада.

### Основные данные

- товары;
- поставщики;
- заказы поставщикам;
- остатки;
- документы закупок;
- финансовые документы.

### Основные проблемы

- ограниченные возможности интеграции;
- сложность внесения изменений;
- большое количество ручных операций.

---

## IS-02. CRM

### Назначение

CRM используется для работы с клиентами.

### Основные функции

- регистрация клиентов;
- хранение контактной информации;
- программа лояльности;
- бонусные счета;
- история покупок;
- маркетинговые кампании.

### Основные пользователи

- маркетинг;
- интернет-магазин;
- сотрудники магазинов.

### Основные данные

- клиенты;
- бонусные счета;
- акции;
- персональные предложения.

### Основные проблемы

- отсутствует сегментация клиентов;
- ограниченные возможности аналитики;
- простые правила начисления бонусов.

---

## IS-03. Интернет-магазин

### Назначение

Обеспечивает продажи через веб-сайт компании.

### Основные функции

- каталог товаров;
- поиск товаров;
- оформление заказа;
- регистрация пользователей;
- прием оплаты;
- просмотр статуса заказа.

### Основные пользователи

- покупатели;
- операторы интернет-магазина.

### Основные данные

- каталог товаров;
- корзины;
- заказы;
- способы оплаты.

### Основные проблемы

- остатки обновляются с задержкой;
- в часы пик снижается производительность.

---

## IS-04. POS

### Назначение

Автоматизация продаж в розничных магазинах.

### Основные функции

- оформление продажи;
- прием оплаты;
- возвраты;
- печать чеков;
- применение скидок.

### Основные пользователи

- кассиры;
- администраторы магазинов.

### Основные данные

- чеки;
- продажи;
- возвраты;
- способы оплаты.

### Основные проблемы

- высокая зависимость от центральных сервисов;
- задержки получения информации о бонусах.

---

## IS-05. WMS

### Назначение

Управление складскими операциями.

### Основные функции

- приемка товаров;
- размещение;
- хранение;
- комплектация заказов;
- инвентаризация;
- отгрузка.

### Основные пользователи

- сотрудники склада;
- начальник склада.

### Основные данные

- складские остатки;
- места хранения;
- задания на комплектацию.

### Основные проблемы

- отсутствует оптимизация размещения товаров;
- часть операций выполняется вручную.

---

## IS-06. BI

### Назначение

Подготовка аналитической отчетности.

### Основные функции

- формирование отчетов;
- анализ продаж;
- анализ закупок;
- анализ клиентов;
- построение дашбордов.

### Основные пользователи

- руководство;
- маркетинг;
- финансовый отдел.

### Основные данные

- продажи;
- закупки;
- клиенты;
- финансовые показатели.

### Основные проблемы

- данные обновляются один раз в сутки;
- отсутствуют прогнозные модели.

---

## IS-07. Integration Platform

### Назначение

Интеграция корпоративных приложений.

### Основные функции

- обмен сообщениями;
- маршрутизация запросов;
- публикация API;
- преобразование сообщений;
- журналирование интеграций.

### Основные пользователи

- ИТ-подразделение;
- разработчики.

### Основные данные

Система не является владельцем бизнес-данных и обеспечивает передачу информации между приложениями.

### Основные проблемы

- часть интеграций реализована напрямую между системами;
- отсутствует единый каталог API;
- недостаточный контроль ошибок интеграции.

# 6. Основные архитектурные проблемы

В результате анализа существующего ландшафта информационных систем были выявлены следующие проблемы:

- отсутствует единая архитектура приложений;
- часть интеграций построена по принципу «точка-точка»;
- бизнес-функции частично дублируются в нескольких системах;
- отсутствует единый каталог сервисов;
- отсутствует единая модель данных;
- масштабирование отдельных приложений затруднено;
- отсутствует централизованное управление API;
- использование облачной инфраструктуры минимально.
