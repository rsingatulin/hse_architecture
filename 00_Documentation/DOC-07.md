# Документ 7. Описание технологической инфраструктуры предприятия (As-Is)

## 1. Общая информация

Информационные системы компании RetailMax размещены в собственном серверном помещении центрального офиса.

Большинство приложений было внедрено в разное время и использует различные технологические платформы. Управление инфраструктурой осуществляется ИТ-отделом компании.

Инфраструктура обеспечивает работу:

- центрального офиса;
- 15 розничных магазинов;
- распределительного склада;
- интернет-магазина;
- удаленных пользователей.

# 6. Сетевое взаимодействие

Все подразделения подключены к центральному офису через корпоративную сеть.

Магазины имеют постоянное подключение к центральному офису.

Распределительный склад подключен по выделенному каналу связи.

Интернет-магазин доступен из сети Интернет.

# 8. Контейнеризация

На момент начала проекта контейнеризация используется ограниченно.

Контейнеры Docker применяются только разработчиками для локального тестирования приложений.

В промышленной эксплуатации контейнерные технологии отсутствуют.

---

# 9. Kubernetes

Kubernetes в компании не используется.

Развертывание приложений выполняется вручную сотрудниками ИТ-отдела.

---

# 10. Облачные технологии

Все корпоративные системы размещены в собственной инфраструктуре предприятия.

Облачные сервисы используются только для:

- корпоративной электронной почты;
- видеоконференций;
- резервного хранения части архивов.

---

# 11. Мониторинг

Мониторинг осуществляется с использованием встроенных средств операционных систем.

Контролируются:

- доступность серверов;
- загрузка процессоров;
- использование памяти;
- свободное место на дисках.

Мониторинг приложений практически отсутствует.

---

# 12. Резервное копирование

Резервное копирование выполняется ежедневно.

Архивируются:

- базы данных;
- файловое хранилище;
- конфигурации серверов.

Проверка восстановления выполняется нерегулярно.

---

# 13. Основные проблемы инфраструктуры

В ходе обследования были выявлены следующие проблемы.

## Архитектурные

- отсутствует единая стратегия развития инфраструктуры;
- приложения развертываются по-разному;
- отсутствует стандартизация среды выполнения.

## Эксплуатационные

- большинство операций выполняется вручную;
- отсутствует автоматическое масштабирование;
- отсутствует автоматическое развертывание новых версий.

## Надежность

- единая точка отказа для некоторых сервисов;
- отсутствует кластеризация приложений;
- ограниченные возможности балансировки нагрузки.

## Мониторинг

- отсутствует централизованная система мониторинга;
- отсутствует сбор журналов приложений;
- отсутствует трассировка запросов между сервисами.

---

# 14. Ограничения

При проектировании целевой технологической архитектуры необходимо учитывать следующие ограничения.

- Замена всех серверов в рамках проекта не предусмотрена.
- Допускается постепенная модернизация инфраструктуры.
- Необходимо обеспечить непрерывную работу магазинов.
- Необходимо сохранить совместимость с существующими информационными системами.
- Новые решения должны обеспечивать возможность масштабирования.
