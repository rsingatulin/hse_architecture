# Документ 15. Каталог информационных сервисов предприятия RetailMax (As-Is)

## 1. Назначение документа

Настоящий документ содержит описание текущего набора информационных сервисов предприятия RetailMax.

Каталог сервисов является частью архитектурного репозитория предприятия и используется для анализа текущего состояния архитектуры (As-Is).

Документ предназначен для:

- анализа распределения ответственности между информационными системами;
- выявления бизнес-доменов;
- определения проблем текущей архитектуры;
- подготовки целевой сервисной архитектуры (To-Be);
- разработки C4-моделей;
- подготовки архитектурных решений (ADR).

---

# 2. Общая характеристика сервисной архитектуры As-Is

Информационная архитектура RetailMax формировалась постепенно.

В результате:

- разные подразделения внедряли системы независимо;
- одна бизнес-функция может поддерживаться несколькими системами;
- отсутствует единый каталог сервисов;
- отсутствуют формальные владельцы сервисов;
- интеграции создавались под конкретные задачи;
- бизнес-логика распределена между приложениями.

Текущее состояние характеризуется высокой связанностью систем и недостаточной прозрачностью архитектуры.

# SRV-01. Управление клиентами

## Общая информация

| Параметр | Значение |
|-|-|
| Идентификатор | SRV-01 |
| Название | Управление клиентами |
| Бизнес-домен | Клиенты и маркетинг |
| Владелец | Отдел маркетинга |
| Основная система | CRM |

---

## Назначение сервиса

Сервис предназначен для хранения информации о клиентах и поддержки взаимодействия с покупателями.

---

## Основные функции

Сервис обеспечивает:

- регистрацию клиентов;
- хранение контактных данных;
- управление профилем клиента;
- ведение истории взаимодействия;
- поддержку программы лояльности;
- сегментацию клиентов.

---

## Основные данные

| Объект данных | Описание |
|-|-|
| Клиент | Основная информация о покупателе |
| Контактные данные | Телефон, email |
| История покупок | Информация о заказах |
| Бонусный счет | Данные программы лояльности |

---

## Потребители сервиса

| Система | Использование |
|-|-|
| Интернет-магазин | Получение информации о клиенте |
| Мобильное приложение | Работа с профилем клиента |
| Аналитическая система | Анализ поведения покупателей |

---

## Проблемы As-Is

- отсутствует единый профиль клиента;
- данные могут дублироваться;
- разные каналы продаж используют различные представления клиента.

# 6. Основные архитектурные проблемы

## 6.1. Отсутствие четких границ ответственности

Некоторые функции реализуются одновременно несколькими системами.

Пример:

- информация о клиенте существует в CRM и интернет-магазине;
- информация о товарах существует в ERP и интернет-магазине.

---

## 6.2. Дублирование данных

Основные проблемные объекты:

- клиент;
- товар;
- заказ;
- остаток.

---

## 6.3. Высокая связанность систем

Изменение одного процесса требует изменений сразу в нескольких системах.

---

## 6.4. Отсутствие единого управления сервисами

Компания не имеет:

- каталога сервисов;
- владельцев сервисов;
- SLA сервисов;
- правил развития сервисов.

---

# 7. Использование документа в проекте

Каталог сервисов используется студентами для:

- анализа текущей архитектуры;
- выделения бизнес-доменов;
- применения Domain-Driven Design;
- проектирования сервисной архитектуры To-Be;
- создания C4 Container Diagram;
- подготовки ADR.

---

# 8. Задание студентам

На основе каталога сервисов необходимо:

1. Проанализировать текущие границы ответственности.
2. Определить проблемные области архитектуры.
3. Выделить бизнес-домены.
4. Предложить целевой каталог сервисов.
5. Определить:

- какие сервисы сохранить;
- какие объединить;
- какие выделить;
- какие создать заново.

6. Подготовить:

- C4 Context Diagram;
- C4 Container Diagram;
- каталог сервисов To-Be;
- минимум 2 ADR по изменению сервисной архитектуры.
