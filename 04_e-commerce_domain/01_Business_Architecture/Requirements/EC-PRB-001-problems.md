# Ключевые проблемы домена интернет-продаж

**Идентификатор:** EC-PRB-001  
**Версия:** 1.0  
**Дата создания:** 2026-09-23  
**Статус:** Черновик  
**Область:** BP-04 «Интернет-продажи»

## Границы анализа

Анализ охватывает интернет-магазин и его взаимодействие с ERP, WMS, CRM, службой доставки и аналитическим контуром в процессе интернет-продаж.

## Реестр проблем

### EC-P-01. Неактуальные остатки товаров

| Поле | Описание |
|---|---|
| Симптом | Интернет-магазин может показать доступный товар, который уже отсутствует на складе. |
| Причина | Каталог и остатки обновляются с задержкой; обмен между интернет-магазином, ERP и WMS не обеспечивает необходимую актуальность данных. |
| Последствия | Возможны отмена заказа, отказ покупателю и снижение доверия к интернет-магазину. |
| Приоритет | Критический |
| Источники | `DOC-03`, `DOC-04`, `DOC-05`, `DOC-06`, `DOC-16` |
| Связанные требования | `REQ-EC-001`, `REQ-EC-002`, `REQ-EC-006`, `REQ-EC-007` |

### EC-P-02. Длительная обработка интернет-заказов

| Поле | Описание |
|---|---|
| Симптом | Среднее время обработки интернет-заказа составляет 30 минут. |
| Причина | Заказ последовательно передаётся между интернет-магазином, ERP, WMS и службой доставки; часть операций зависит от задержек обмена данными. |
| Последствия | Увеличивается время ожидания покупателя и снижается качество обслуживания. |
| Приоритет | Высокий |
| Источники | `DOC-03`, `DOC-05`, `DOC-08`, `DOC-10` |
| Связанные требования | `REQ-EC-002`, `REQ-EC-003`, `REQ-EC-006`, `REQ-EC-007` |

### EC-P-03. Снижение производительности в периоды пиковых нагрузок

| Поле | Описание |
|---|---|
| Симптом | Во время маркетинговых акций сайт может работать медленнее. |
| Причина | Текущая архитектура ограничена возможностями отдельных систем и недостаточно подготовлена к резкому росту нагрузки. |
| Последствия | Покупатели дольше оформляют заказы, а интернет-магазин теряет часть потенциальных продаж. |
| Приоритет | Высокий |
| Источники | `DOC-04`, `DOC-08`, `DOC-11`, `DOC-17` |
| Связанные требования | `REQ-EC-004`, `REQ-EC-005` |

### EC-P-04. Точечные интеграции и отсутствие единого управления обменом

| Поле | Описание |
|---|---|
| Симптом | Между информационными системами используются отдельные связи, разные форматы сообщений и несколько способов обмена. |
| Причина | Интеграции развивались независимо; отсутствуют единые контракты, централизованное управление API и полноценное версионирование. |
| Последствия | Изменение одной системы усложняет сопровождение соседних интеграций и повышает стоимость развития. |
| Приоритет | Высокий |
| Источники | `DOC-05`, `DOC-12`, `DOC-13`, `DOC-16`, `DOC-17` |
| Связанные требования | `REQ-EC-006`, `REQ-EC-007`, `REQ-EC-008` |

### EC-P-05. Дублирование клиентских данных

| Поле | Описание |
|---|---|
| Симптом | При передаче данных клиента между интернет-магазином и CRM возможны дубли карточек. |
| Причина | Не используется единый идентификатор клиента и отсутствуют правила автоматического разрешения конфликтов данных. |
| Последствия | История взаимодействия с покупателем становится неполной, а маркетинговые и персональные предложения могут формироваться некорректно. |
| Приоритет | Высокий |
| Источники | `DOC-05`, `DOC-06`, `DOC-12`, `DOC-16` |
| Связанные требования | `REQ-EC-009`, `REQ-EC-010` |

### EC-P-06. Ручная обработка ошибок интеграции

| Поле | Описание |
|---|---|
| Симптом | Ошибки обмена данными сложно контролировать, а обработка некоторых сбоев требует ручного вмешательства. |
| Причина | Отсутствуют единые механизмы мониторинга, повторной обработки и централизованного управления ошибками интеграций. |
| Последствия | Заказы и статусы могут обрабатываться с задержкой или повторно, а поиск причины ошибки занимает больше времени. |
| Приоритет | Высокий |
| Источники | `DOC-05`, `DOC-07`, `DOC-16`, `DOC-17` |
| Связанные требования | `REQ-EC-006`, `REQ-EC-007`, `REQ-EC-008` |

### EC-P-07. Несвоевременная аналитическая информация

| Поле | Описание |
|---|---|
| Симптом | Аналитические отчёты формируются один раз в сутки, поэтому данные быстро устаревают. |
| Причина | Данные из ERP и CRM передаются в аналитический контур пакетно. |
| Последствия | Руководство и маркетинг не могут своевременно оценивать продажи, поведение клиентов и результаты акций. |
| Приоритет | Средний |
| Источники | `DOC-03`, `DOC-05`, `DOC-08`, `DOC-11`, `DOC-16` |
| Связанные требования | `REQ-EC-010` |

### EC-P-08. Медленный выпуск новых функций и отсутствие персональных рекомендаций

| Поле | Описание |
|---|---|
| Симптом | Руководитель интернет-магазина отмечает необходимость быстрее выпускать новые функции; покупатели ожидают персональных рекомендаций и удобного поиска. |
| Причина | Существующие системы и интеграции тесно связаны, а персонализация не выделена в отдельную архитектурную возможность. |
| Последствия | Интернет-магазин медленнее реагирует на ожидания покупателей и изменения рынка. |
| Приоритет | Высокий |
| Источники | `DOC-08`, `DOC-11`, `DOC-12`, `DOC-13` |
| Связанные требования | `REQ-EC-008`, `REQ-EC-010` |

## Приоритеты проблем

В первую очередь необходимо устранить проблемы, которые влияют на достоверность наличия товара, обработку заказа и устойчивость интеграций: `EC-P-01`, `EC-P-02`, `EC-P-03`, `EC-P-04` и `EC-P-06`.

Проблемы `EC-P-05`, `EC-P-07` и `EC-P-08` следует учитывать при проектировании целевой архитектуры данных, аналитики и сервисов интернет-магазина.
