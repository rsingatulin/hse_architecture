# Паспорт проекта — Домен «Закупки»

## 1.1. Общие сведения

| Параметр | Значение |
|----------|----------|
| Наименование проекта | Оптимизация архитектуры бизнес-процесса «Закупка товаров» в RetailMax |
| Заказчик проекта | Генеральный директор RetailMax |
| Куратор проекта | ИТ-директор |
| Руководитель проектной группы | Менеджер по закупкам (владелец процесса) |
| Дата начала | 1 сентября 20XX года |
| Планируемая продолжительность | 12 месяцев |
| Максимальный бюджет | 850 000 у.е. (общий бюджет проекта; для домена закупок — доля, определяемая при планировании) |
| Плановый срок эксплуатации | 5 лет |

## 1.2. Основание для запуска проекта

Существующая архитектура поддержки процесса закупок не обеспечивает необходимую скорость и эффективность:

- Среднее время обработки закупки составляет **2 рабочих дня**;
- Отсутствует прогнозирование спроса — потребность формируется вручную;
- Высокая доля ручных операций при согласовании заказов;
- ERP является основной системой, но имеет ограниченные возможности интеграции;
- Отсутствует единая модель данных для планирования закупок.

## 1.3. Цель проекта

Разработать целевую архитектуру поддержки процесса «Закупка товаров», обеспечивающую:

- Сокращение времени обработки закупки с 2 дней до ≤4 часов;
- Автоматизацию формирования потребности на основе прогнозирования спроса;
- Прозрачную интеграцию ERP с WMS и CRM для актуальных данных об остатках и продажах;
- Поддержку принятия решений с использованием ИИ.

## 1.4. Задачи проекта

1. Проанализировать текущий процесс закупок (As-Is);
2. Выявить проблемы и узкие места процесса;
3. Разработать целевую модель процесса (To-Be);
4. Спроектировать архитектуру приложений для поддержки закупок (ERP, WMS, Integration Platform);
5. Определить требования к данным (остатки, поставщики, заказы);
6. Разработать интеграционную архитектуру (API, событийная шина);
7. Оценить возможности использования ИИ для прогнозирования;
8. Подготовить ТЭО и план внедрения.

## 1.5. Границы проекта

**Входит:**

- Бизнес-процесс BP-02 «Закупка товаров»;
- ИС: ERP (IS-01), WMS (IS-05), Integration Platform (IS-07);
- Данные: товары, поставщики, заказы поставщикам, остатки, документы закупок;
- Интеграции между ERP, WMS и внешними системами поставщиков.

**Не входит:**

- Процессы продаж, склада (в части исполнения), интернет-продаж;
- Разработка ПО;
- Изменение оргструктуры;
- Миграция данных.

## 1.6. Ограничения

- ERP не заменяется;
- Решения должны быть совместимы с существующей ИТ-инфраструктурой;
- Компания продолжает работу во время внедрения.

## 1.7. Критерии успешного завершения

- Разработана целевая архитектура процесса закупок;
- Подготовлены модели As-Is и To-Be (BPMN);
- Определены архитектурные требования;
- Разработан план интеграции ERP-WMS;
- Подготовлено ТЭО и реестр рисков.
