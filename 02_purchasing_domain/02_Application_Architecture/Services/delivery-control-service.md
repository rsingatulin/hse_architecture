### Сервис контроля исполнения и сверки (Delivery Control Service)

**Назначение**

Сравнение плановых данных заказа с фактическими данными приемки от WMS, выявление расхождений и инициирование претензионной работы.

**Владелец сервиса**

Отдел закупок (Контролер / Менеджер по закупкам).

**Ответственность сервиса**

Сервис отвечает за:
* Сверку факта поставки с планом (заказом).
* Фиксацию расхождений (недовоз, пересорт, брак).
* Инициирование и ведение процесса претензий к поставщикам.

**Используемые данные**
| Объект данных | Операции |
|---|---|
| Факт поставки | Read |
| Расхождение | Create, Read |
| Претензия | Create, Read, Update |

**API**
| Метод | Назначение |
|---|---|
| `POST /api/v1/reconciliation/receive-fact` | Получение события о фактической приемке от WMS |
| `GET /api/v1/reconciliation/discrepancies` | Получение списка выявленных расхождений |
| `POST /api/v1/reconciliation/claims` | Создание претензии к поставщику |

**Потребители сервиса**
| Система | Назначение |
|---|---|
| WMS | Отправка событий о фактической приемке товара (событийная модель) |
| ERP / Финансы | Корректировка финансовых обязательств на основе актов расхождений |
| Сервис управления заказами | Закрытие заказа на основании результатов сверки |

**Нефункциональные характеристики**
| Параметр | Значение |
|---|---|
| Доступность | 99,5% |
| Производительность | Время ответа не более 1 секунды |
| Масштабирование | Горизонтальное |
