# Архитектурное проектирование блока «Закупки» (BP-02)

## Таблица доменов

| Уровень | Элемент | Тип (по DDD) | Обоснование (на основе документов кейса) |
| :--- | :--- | :--- | :--- |
| **Domain** | **Закупки** (Procurement) | **Supporting Domain** | Обеспечивает товарное наполнение компании. Критически важен для бизнеса, но не является основной ценностью для клиента. |
| **Subdomain** | **Управление поставщиками** (Supplier Management) | Supporting | Ведение справочника контрагентов, условий договоров, рейтингов надежности и истории взаимодействий. Владелец данных: Отдел закупок, объект D-04 «Поставщик» (DOC-06). |
| **Subdomain** | **Управление ассортиментом и матрицей закупок** | Supporting | Формирование товарной матрицы, ввод новых и вывод неликвидных товаров. Указано как основная функция отдела закупок в оргструктуре (DOC-02). |
| **Subdomain** | **Прогнозирование потребности и планирование** | Supporting *(Strategic)* | Согласно интервью (DOC-11), сейчас процесс ручной. Внедрение аналитики/AI для прогнозирования на основе продаж, остатков и сезонности станет ключевым драйвером оптимизации запасов (Стратегия, DOC-08). |
| **Subdomain** | **Управление заказами поставщикам** (Purchase Order Management) | **Core** (для данного домена) | Ключевая бизнес-ценность процесса BP-02 (DOC-03): своевременное, корректное формирование, согласование и отслеживание заказа (объект D-05) до момента его исполнения. |
| **Subdomain** | **Контроль исполнения и сверка поставок** | Supporting | Связующее звено с WMS. В отличие от физической приемки (которая в WMS), этот поддомен отвечает за сверку факта поставки с заказом, учет расхождений и управление претензиями (DOC-03, DOC-11). |
| **Subdomain** | **Финансовое согласование закупок** | Generic | Стандартная бизнес-процедура согласования оплат с Финансовым отделом (DOC-03). |
| **Subdomain** | **Интеграция с поставщиками** (Supplier Integration / EDI) | Supporting *(Technical)* | Критическая зона модернизации. Замена текущих ручных файловых обменов (DOC-16, INT-003) на стандартизированные API или портал поставщиков для автоматизации (DOC-08, Принцип API First, DOC-13). |
| **Subdomain** | **Аналитика и отчетность по закупкам** | Generic | Формирование KPI (оборачиваемость, уровень сервиса поставщиков), выгрузка данных в DWH/BI (SRV-07). Является потребителем данных. |

## Bounded Context 

| Bounded Context | Границы | Ubiquitous Language | Владелец | Ключевые данные |
| :--- | :--- | :--- | :--- | :--- |
| **Управление поставщиками**<br>*(Supplier Management)* | Отвечает за создание, верификацию, классификацию и оценку надежности контрагентов. **Не включает** финансовые расчеты (домен «Финансы») или оценку качества физической приемки (домен «Логистика»). | Поставщик, Договор, Рейтинг надежности, Условия поставки, Категория поставщика, Черный список. | Отдел закупок | **D-04 Поставщик**: код, наименование, реквизиты, условия договора, статус, рейтинг (DOC-06). |
| **Планирование и прогнозирование**<br>*(Procurement Planning)* | Анализ потребностей и формирование планов закупок на основе остатков, истории продаж и сезонности. Граница заканчивается на этапе формирования рекомендации или плана, до создания юридического документа. | Потребность в закупке, Прогноз спроса, Точка заказа, Страховой запас, Неликвид, Товарная матрица. | Отдел закупок (Менеджер по закупкам / Аналитик) | Параметры планирования (мин/макс запас), прогнозные данные, сформированная потребность в товаре. |
| **Управление заказами поставщикам**<br>*(Purchase Order Management)* | Преобразование плана в конкретный заказ, внутреннее согласование, отправка поставщику и отслеживание статуса. **Не включает** физическую приемку товара (WMS) и фактическую оплату счетов (Финансы). | Заказ поставщику (PO), Строка заказа, Статус заказа (Создан, Согласован, Отправлен, Подтвержден), Срок поставки, Спецификация. | Отдел закупок (Менеджер по закупкам) | **D-05 Закупка**: номер, дата, поставщик, список товаров, количество, цена, статус выполнения (DOC-06). |
| **Контроль исполнения и сверка**<br>*(Delivery Control & Reconciliation)* | Сравнение плановых данных заказа с фактическими данными приемки, полученными от WMS. Выявление расхождений и инициирование претензионной работы. **Не включает** физическое перемещение или размещение товара на складе. | Факт поставки, Расхождение, Недовоз, Пересорт, Претензия, Акт сверки. | Отдел закупок (Менеджер по закупкам / Контролер) | События приемки (агрегированные из WMS), акты расхождений, статусы закрытия заказов, претензионная документация. |
| **Интеграция с поставщиками**<br>*(Supplier Integration)* | Технический и процессный слой взаимодействия с внешними системами поставщиков (порталы, API). Трансляция внутренних моделей заказов во внешние форматы и обратно. Не содержит бизнес-логики принятия решений о закупке. | Подтверждение заказа (Order Acknowledgement), Уведомление об отгрузке, API-шлюз поставщика, Маппинг данных. | ИТ-отдел (Архитектор интеграций) при бизнес-владении Отдела закупок | Маппинги форматов данных, логи обмена сообщениями, статусы доставки, внешние идентификаторы поставщика. |
