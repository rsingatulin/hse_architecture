# **ADR-RT-04. Сервисы искусственного интеллекта и машинного обучения: прогноз оттока и сегментация в рамках сервиса рекомендаций**

| Поле | Значение |
| ----- | ----- |
| Версия / дата | 1.0 / 12.11.2026 |
| Статус | Предложено; владение сервисом рекомендаций зафиксировано за командой retention |
| Проблемы | RT-P-14 — отсутствие прогнозных моделей; RT-P-15 — следующее наилучшее действие не определено; RT-P-16 — среда выполнения моделей машинного обучения не определена |
| Требования | AI-RET-01/02/04/05/06, TA-RET-02, принцип 12 DOC-13 |
| Участники | Команда retention, интернет-магазин, маркетинг, безопасность, эксплуатация |

## **Контекст**

Архитектурный комитет определил один логический сервис рекомендаций: алгоритм, расчёт и хранилище результатов — за командой retention, места показа и события — за интернет-магазином; фоновый пересчёт, контекстный резерв, правила до машинного обучения. Домен retention дополнительно требует модель оттока (AI-RET-01), следующее наилучшее действие (AI-RET-02), сегментацию (AI-RET-06) при ответственном использовании искусственного интеллекта (DOC-13: качество данных, прозрачность, контроль человеком).

## **Рассматриваемые варианты**

| Вариант | Преимущества | Недостатки / причина отказа |
| ----- | ----- | ----- |
| Машинное обучение внутри CRM/BI | Нет нового контура | Нагрузка на операционные и аналитические системы, связанные релизы |
| Отдельные сервисы машинного обучения с пакетным скорингом на витринах RT-002; результаты — события и готовые наборы; оперативный вывод только в контракте сервиса рекомендаций | Контролируемая стоимость, воспроизводимость, соответствие корпоративным стандартам; **выбран** | Периодичность может отставать от последнего действия пользователя |
| Полный оперативный вывод на каждый запрос | Максимальная свежесть | Задержка, стоимость, не нужна для прогноза оттока |

## **Выбранное решение**

* **Прогноз оттока**: пакетный скоринг (ежечасно/ежедневно) на признаках витрин; выход — идентификатор клиента, оценка риска, коды причин, версия модели, дата актуальности; публикация события «риск оттока изменён» → триггер кампаний удержания (RT-003). Объяснимость через коды причин; запуск кампаний — с контролем маркетолога (настраиваемо).  
* **Следующее наилучшее действие**: рассчитывается внутри сервиса рекомендаций с использованием витрин и бонусного контекста из проекции лояльности (RT-001); отдельного мастера следующего наилучшего действия нет; POS и сайт получают предложения по контракту сервиса рекомендаций.  
* **Сегментация**: пакетная кластеризация → метки сегментов в витринах с интерпретируемыми профилями → потребители сервиса кампаний и BI.  
* **Выполнение и версии**: модели — версионируемые артефакты выпуска, развёртывание — контейнеры; хранилище признаков, Redis и векторные базы данных по умолчанию **не вводятся** (сохранение контракта сервиса рекомендаций).  
* **Управление**: контроль качества данных (DA-RET-04), контроль доступа к персональным наборам, инвалидация при отказе от персонализации, опытная эксплуатация против базового варианта простыми правилами, рост продаж не заявляется до измерения.

## **Обоснование**

Пакетный скоринг отделяет вычисления от пользовательских запросов, переиспользует витрины и аналитику команды retention, не создаёт второго профиля клиента и остаётся в рамках ответственности сервиса рекомендаций.

## **Связанные требования**

| Требование | Как поддерживается |
| ----- | ----- |
| AI-RET-01 | События оттока → триггеры удержания |
| AI-RET-02 | Следующее наилучшее действие в контракте сервиса рекомендаций |
| AI-RET-04/05/06 | Рекомендации, прогноз спроса/поведения, кластеризация на витринах |
| TA-RET-02 | Контейнеризация сервисов машинного обучения |

## **Последствия и риски**

Отставание персонализации от последнего действия (свежие ограничения каталога применяются при показе); зависимость качества моделей от хранилища данных; риск непрозрачных решений — коды причин и человеческий контроль.

## **Проверка**

| Проверка | Ожидаемый результат |
| ----- | ----- |
| Устаревшие признаки | Дата актуальности в результате, витрина не отображается как свежая |
| Отказ от персонализации | Исключение из выдачи и отката |
| Откат версии модели | Активна прежняя версия, частичный расчёт не виден |
| Двойной триггер кампании по одному риску | Идемпотентность RT-001/RT-003 |
