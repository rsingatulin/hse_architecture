## **ADR-RT-03. Campaign Service и триггерная автоматизация**

| Поле | Значение |
| ----- | ----- |
| Версия / дата | 1.0 / 12.11.2026 |
| Статус | Предложено |
| Проблемы | RT-P-11 — ручные запуски акций; RT-P-12 — медленная сегментация; RT-P-13 — нет A/B и оперативного контроля эффективности |
| Требования | BR-RET-05, BR-RET-06, AA-RET-05, BA-RET-02, SA-RET-01/03, AI-RET-06 |
| Участники | Команда retention, маркетинг, Loyalty (RT-001), каналы коммуникации, безопасность, интернет-магазин |

### **Контекст**

As-Is: маркетолог настраивает акции в CRM, запуск преимущественно ручной, эффективность видна лишь после суточного ETL. Цели: автоматический запуск по триггерам, сегментация за минуты, A/B-тестирование, контроль в реальном времени.

### **Рассматриваемые варианты**

| Вариант | Преимущества | Недостатки / причина отказа |
| ----- | ----- | ----- |
| Автоматизация внутри CRM | Нет нового сервиса | Связанные релизы, нагрузка на OLTP, противоречит AA-RET-01/05 |
| Отдельный Campaign Service: правила и триггеры на событиях, сегменты из витрин RT-002, отправка через адаптеры каналов общего слоя, собственный журнал | Независимое развитие, A/B, частотные лимиты, наблюдаемость; **выбран** | Новый компонент; контракты с внешними каналами |
| Внешняя SaaS-платформа маркетинг-автоматизации | Быстрый старт | Экспорт ПДн, бюджет, интеграционная сложность; не исключается позже |

### **Выбранное решение**

Campaign Service владеет: описанием кампаний и версий, правилами триггеров, сегментными выборками, частотными лимитами (caps), распределением A/B (по хешу customerId), журналом отправок и метриками эффективности. Состояние согласий/отказов от маркетинга — в CRM (часть профиля), читается через общий слой; отказ блокирует отправку. Бонусы как содержание предложения выдаются командой в Loyalty Service (RT-001), не «напрямую в баланс». Отправка — через согласованные адаптеры каналов (email, SMS, push) строго по корпоративному стандарту.  
Триггеры: ChurnRiskChanged (RT-004), день рождения, брошенная корзина (события интернет-магазина), истечение бонусов, смена сегмента. Эффективность фиксируется событиями показов/кликов и фактами продаж в витринах.

### **Обоснование**

Выполняет BR-RET-05/06 и AA-RET-05 без расширения монолита CRM; триггерная модель согласована с BA-RET-02 и корпоративным стандартом интеграции.

### **Связанные требования**

| Требование | Как поддерживается |
| ----- | ----- |
| BR-RET-05 | Сегменты из витрин, запуск за минуты |
| BR-RET-06 | Триггеры, A/B, контроль в реальном времени |
| SA-RET-01/03 | Роли, согласие, аудит отправок |

### **Последствия и риски**

Новый сервис и контракты каналов; риск «шума» при ошибочных триггерах — частотные лимиты и pre-flight-проверки; нагрузка на общий слой в пик кампаний — лимиты и планирование отправок.

### **Проверка**

| Проверка | Ожидаемый результат |
| ----- | ----- |
| Отказ клиента от рассылок | Нет отправки, запись в журнале |
| Превышение cap | Подавление без потери кампании |
| Дубль триггера | Идемпотентно по eventId |
| CRM недоступна | Кампании в очереди, не теряются |
